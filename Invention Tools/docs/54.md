Migration and Immigrants 

Migration and immigrants are like the bloodstream of human history — people moving, carrying their skills, beliefs, food, and labor into new territories. Borders look permanent on maps, but in reality, they’re porous lines drawn by politics; people have always flowed across them.

Here’s the lay of the land:

Migration is the act of moving from one place to another — can be within a country (internal migration, like rural to urban) or across borders (international migration). Motivations fall into two big buckets:

Push factors: war, persecution, poverty, climate change, lack of opportunity.

1. Azure DevOps Process Model (CMMI template)
Azure DevOps supports multiple process templates (Agile, Scrum, Basic, CMMI).

CMMI (Capability Maturity Model Integration) is built for requirements-heavy projects, with full hierarchy and states.

Work item types in CMMI process:

Epic (portfolio level, long-term initiative).

Feature (large deliverable grouping requirements).

Requirement (user/business requirement, can be functional or non-functional).

Task (unit of work tied to a requirement).

Bug (defects, also linked to requirements).

Each of these has states and workflow transitions pre-defined.

2. Work Item Relationships
Epic → Feature: Epics break down into multiple Features.

Feature → Requirement: Each Feature is composed of multiple Requirements.

Requirement → Task: Each Requirement is fulfilled by Tasks.

Task → Sub-task: Tasks can be broken into smaller sub-tasks (customizable).

Bug: Can link to Requirement, Task, or Feature (depending on where it’s discovered).

Linking types in Azure DevOps:

Parent/Child (hierarchy).

Related (loose association).

Predecessor/Successor (dependency).

Tests (requirements linked to test cases).

3. Workflows (states per item type)
Epic: New → Active → Resolved → Closed.

Feature: New → Active → Resolved → Closed.

Requirement: Proposed → Active → Resolved → Closed.

Task: To Do → In Progress → Done.

Bug: New → Active → Resolved → Closed.

(These states can be customized per org; you can add gates like “On Hold,” “Blocked,” or “Ready for Review.”)

4. Work Time & Estimation
Azure DevOps supports:

Effort (Story Points or Custom “Estimate” field) → at Requirement/Task level.

Remaining Work → hours left, updated daily.

Completed Work → auto-rolls up from sub-tasks.

Original Estimate / Remaining Work / Completed Work → three key time fields in CMMI.
Roll-up: Sub-task → Task → Requirement → Feature → Epic. Dashboards give burndown/burn-up charts.

Use Iteration Paths = timeboxes (Sprints, Quarters, or Projects).

Epics/Features often stretch across multiple iterations; tasks are sprint-bounded.
